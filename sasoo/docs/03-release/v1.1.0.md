# Sasoo v1.1.0 릴리스 노트 초안

## 사용자 변경

- 질문 패널을 "사수와 토의"로 바꾼다. 사수는 사용자의 해석에서 논문이 실제로 뒷받침하는 범위를 먼저 인정하고, 넘어선 부분은 근거 위치와 함께 짚는다. 더 비판적으로 따져 달라고 하면 근거가 있는 범위 안에서 반론을 먼저 말한다.
- 토의가 논문마다 저장된다. 논문을 바꾸거나 앱을 다시 시작해도 이어서 볼 수 있다. 이전에는 화면 메모리에만 있었고, 최근 20개 메시지만 알리지 않고 보냈다.
- 입력창 위 맥락 막대(예: "맥락 7.8K / 260K 토큰")가 사수가 보는 맥락의 크기를 보여 준다. 막대를 누르면 출처별 추정 토큰과 잘린 분석 단계를 볼 수 있다.
- "새 맥락"으로 기록은 남긴 채 이후 대화만 사수에게 보낸다. 재분석이 끝났거나 맥락 예산(260K 토큰)을 넘으면 자동으로 새 맥락을 시작한다. 이전 맥락의 대화는 접어 두고, 펼치면 흐리게 보인다.
- 중지하거나 끊긴 답은 "중단됨"으로 남고 사수에게 다시 보내지 않는다. 토의 삭제는 더보기 메뉴에서 확인 뒤 실행한다.
- DOI가 있는 새 논문은 OpenAlex 소분야로 담당 에이전트를 정한다. 맞는 전문 에이전트가 없으면 일반 에이전트가 맡고, 토의 카드 부제에 OpenAlex 대분야명을 보인다. 기존 논문의 배정은 바꾸지 않는다.
- 담당 에이전트를 영어 이름으로 표시하고, 아바타 머리글자를 두 글자로 바꾼다.
- 논문을 삭제하면 저장된 읽기 안내도 함께 지운다.

## 호환성과 확인 범위

- DB에 `discussion_messages` 테이블과 `papers.openalex_subfield_id` 컬럼이 추가된다. 앱 시작 시 자동으로 만들며 기존 데이터는 바꾸지 않는다.
- 읽기 안내는 토의 기록에 남기지 않는다.
- OpenAlex 조회는 키 없이 하고, 실패하면 키워드 분류로 돌아간다. 업로드에 최대 3초가 더 걸릴 수 있다.
- 말투와 맥락 동작은 논문 2편, 두 공급사에서 확인했다(`docs/validation/2026-10-09-discussion-stage1-tone-gate.md`, `docs/validation/2026-10-09-discussion-stage2.md`). 분석 결과의 과학적 정확성이 새로 검증됐다는 뜻은 아니다.
- 맥락 예산 근처의 턴에서는 토큰 계산 때문에 첫 응답이 약 0.7~0.9초 늦어질 수 있다.

## 배포 절차

1. 릴리스 PR의 Windows Build Check를 확인하고 main에 병합한다.
2. 병합된 정확한 main 커밋에 `v1.1.0` 태그를 만들고 push한다.
3. Release 워크플로의 macOS/Windows 산출물과 업데이트 manifest를 검증한다. 워크플로는 GitHub draft release를 만든다.
4. 노트를 검토한 뒤 공개하고, 자산 8종과 공개 URL 응답을 확인한다.

release.yml은 태그와 버전, 태그와 빌드 커밋의 일치, 빌드 커밋의 main 포함 여부를 검사한다. 기존 릴리스나 draft가 있으면 중단하므로, 태그 실행 전에 빈 draft를 미리 만들지 않는다.

## 설치 안내

v1.0.2와 같다. macOS는 미서명/미공증 앱이고, Windows는 미서명 설치 파일이라 SmartScreen 확인이 나타날 수 있다.
