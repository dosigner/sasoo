# Sasoo v0.6.5 Follow-up Plan

## Summary

This follow-up thread covers only the deferred work left after the v0.6.5 UI clarity pass:

1. Electron runtime manual usability validation
2. legacy chat CSS cleanup after the docked chat redesign
3. substantive Agents information architecture redesign

This order is intentional:

- runtime QA may reveal regressions that should change cleanup priorities
- chat CSS cleanup is bounded and should happen before a broader UI restructuring pass
- Agents IA redesign is the broadest and most decision-heavy surface, so it should start from a verified baseline

This document is intended to be the handoff artifact for a new thread.

## Workstream 1: Electron Runtime Manual Validation

### Goal

Validate the current v0.6.5 UI behavior in the real Electron desktop runtime, not only in the browser-built frontend.

### Validation Scope

Run the following end-to-end flows in the packaged or local Electron app:

1. Upload flow
   - upload PDF
   - reach classified handoff state
   - confirm CTA label and real behavior match
   - confirm assigned domain/agent handoff block is understandable

2. Workbench analysis flow
   - open workbench from upload
   - start analysis
   - verify sticky status rail is always visible
   - verify partial-result states are understandable without guessing
   - inspect tab switching across `요약`, `Figures`, `Recipe`, `실험계획`

3. Docked chat flow
   - verify disabled state before screening completes
   - verify enabled state after screening completes
   - verify streaming behavior while docked
   - verify no accidental dismissal path remains

4. Library re-entry flow
   - reopen papers in `pending`, `analyzing`, `completed`, `error`
   - confirm primary action labels match paper state
   - confirm overflow menu is discoverable and usable

5. Navigation and shell flow
   - move between Upload, Library, Agents, Settings, Workbench
   - confirm standard page scaffold and Workbench scaffold feel intentionally different
   - confirm sidebar ordering reflects actual product usage

6. Resize and density flow
   - resize PDF split via mouse and keyboard
   - resize docked chat width by window size changes
   - test reduced-width desktop window behavior
   - confirm no critical content becomes inaccessible

### Output Format

Record each finding as:

- `PASS`
- `FAIL - blocker`
- `FAIL - regression`
- `FAIL - polish`

Each finding should include:

- surface
- exact scenario
- observed behavior
- expected behavior
- severity
- next action

## Workstream 2: Legacy Chat CSS Cleanup

### Audit Target

- `chat-launcher`
- `chat-sheet-*`
- overlay, scrim, and backdrop variants
- old mobile/responsive branches that existed only for floating chat

### Keep These Shared Chat Primitives

Do not remove styles still used by the docked panel:

- `chat-starter-chip`
- `chat-empty-state`
- `chat-empty-icon`
- `chat-bubble*`
- `chat-follow-*`
- `chat-composer*`
- `chat-send-button`

### Cleanup Rules

- Remove only styles that are provably unused by current React code.
- After deleting CSS, confirm there are no remaining React references to removed class names.
- If an old class is still referenced by an unused or obsolete component, either:
  - remove that component in the same follow-up thread, or
  - mark it clearly as deprecated and document why it remains

## Workstream 3: Agents Information Architecture Redesign

### Goal

Redesign the Agents authoring experience as a product/UX problem, not a cosmetic pass, while preserving the current backend contract and agent data model unless a hard blocker is discovered.

### Core Direction

Split the experience into two levels:

1. basic authoring flow
2. advanced prompt and system tuning

### Default Authoring Flow

The default guided flow should be:

1. identity
2. domain routing
3. recipe parameters
4. behavior preview
5. advanced prompts

### Structural Requirements

- Move prompt-heavy controls out of the first-run primary experience.
- Keep advanced prompt editing available, but visually and structurally demote it.
- Distinguish safe/default settings from expert/risky settings.
- Preserve these capabilities:
  - import
  - export
  - duplicate
  - enable/disable
  - raw edit

These remain supported, but should no longer dominate the initial visual hierarchy.

### Preview Requirements

Add stronger preview surfaces that help users understand:

- how the agent will appear in the app
- how the agent will be routed
- what outputs it will emphasize
- what tone it is likely to use

If feasible without backend changes, include an example response/tone snippet. If not feasible, document the gap as a separate follow-up rather than bundling a hidden backend requirement into this redesign.

### Microcopy Requirements

Update Korean microcopy to reduce the feeling of raw admin tooling and make consequences clearer, especially around:

- changing routing fields
- changing recipe parameter emphasis
- editing advanced prompts
- saving vs reviewing

### Constraint

Do not assume backend API, schema, or database changes are available by default.

If the redesign exposes a missing preview or evaluation capability that truly requires backend support, document that as:

- blocked by backend enhancement
- separate follow-up
- not part of the initial IA refactor itself

## Public Interfaces and Constraints

- No required backend API changes are assumed.
- No schema or database changes are assumed.
- The release checklist should be updated if runtime QA shows the documented behavior is outdated.
- This follow-up should stay as one thread, not split into separate planning tracks.
