# 논문 실험 MVP 확정 명세

상태: 2026-09-07 사용자 확정. 이 문서는 대화에서 합의한 제품 범위다. 구현 방법과 검증 순서는 [구현 계획](../plans/2026-09-07-paper-experiment-mvp.md)에 구분해 기록한다.

## 1. 목적

논문의 핵심 방법을 깊이 이해하는 시간을 줄인다. 사용자는 논문 속 로봇을 작은 실험에서 움직이고, 자연어로 변수와 최소 구현을 바꾸며, 결과가 달라지는 이유를 배운다.

성공은 화면 생성이나 로봇의 움직임만으로 판정하지 않는다. 새로운 조건의 결과를 예상하고, 방법의 작동 이유와 실패 조건을 설명할 수 있어야 한다. 첫 학습 20분은 제품 목표이며, 학습 효과가 검증된 수치는 아니다.

## 2. 확정 범위

| ID | 요구사항 |
|---|---|
| R1 | 워크벤치에 별도 `실험` 탭을 제공한다. 사용자가 시작할 때 준비하며, 논문 업로드나 탭 조회만으로 생성하지 않는다. |
| R2 | 기존 논문 분석과 연구자 설정을 재사용한다. 설명 수준을 다시 질문하지 않는다. |
| R3 | 논문 전체의 핵심 개념을 연결한 짧은 학습 코스를 구성한다. 모든 절에 실험을 억지로 배정하지 않는다. |
| R4 | 로보틱스 논문을 첫 검증 대상으로 삼는다. 논문 속 로봇의 구조와 연구에 중요한 특성을 유지한다. |
| R5 | 저자의 프로젝트 페이지와 공개 저장소까지 찾아 로봇 모델, 코드, 설정과 관련 자료를 확보한다. |
| R6 | Sasoo 내부 HTML 실험 환경에서 사용자 컴퓨터의 자원으로 실행한다. 외부 GPU와 독립 실행 파일 내보내기는 첫 범위에 없다. |
| R7 | 첫 실행 실험 준비 목표는 5분 이내다. 준비되는 설명은 먼저 보여준다. |
| R8 | 논문에 없는 가정과 교육용 축소 구현은 이유 및 해석의 한계를 설명하고, 사용자가 확인한 뒤 적용한다. |
| R9 | 핵심 설명 → 결과 예상 → 실행과 비교 → 필요한 부분의 추가 설명으로 학습한다. |
| R10 | 예상 질문은 항상 건너뛸 수 있다. 건너뜀은 미확인이며, 이해 부족이나 이해 완료로 바꾸지 않는다. |
| R11 | 사용자는 자연어로 변수와 최소 구현을 변경한다. 원래 모델과 비교하고 이전 실행 가능한 상태로 돌아갈 수 있다. |
| R12 | 논문별 짧은 학습 메모 하나를 저장하고 다음 턴에 반영한다. 확인된 이해, 관찰된 혼동, 미확인을 구분한다. |
| R13 | 학습 메모는 필요할 때 펼쳐 본다. 사용자의 자연어 정정을 반영한다. |
| R14 | 논문별 진행과 실험 기록을 분리한다. 논문 간 개념 이해 공유나 전역 학습 상태는 만들지 않는다. |
| R15 | 시간 초과 또는 준비 실패 시 준비된 설명과 막힌 이유를 보존하고 자동 재시도를 멈춘다. 재시도는 사용자 동작으로 시작한다. |
| R16 | 원문 근거, 사용 자료의 버전, 추가 가정, 실행 설정과 결과를 연결해 보존한다. |

## 3. 로봇과 모델의 충실도

교육용 최소 구현은 임의의 다른 로봇으로 대체한다는 뜻이 아니다. 로봇의 식별, 관절 구조, 자유도, 센서와 구동기 중 학습 주제에 영향을 주는 부분을 논문 및 공개 자료와 대조한다.

외형 일치, 동역학 파라미터 일치, 제어 방법 일치, 성능 재현은 별도로 표시한다. 확인되지 않은 질량이나 마찰값을 추정했다면 그 근거와 영향에 대한 확인을 받는다. 로봇 구조를 확보하지 못했을 때는 자료 부족으로 표시하고, 다른 기본 로봇을 원문 로봇처럼 보여주지 않는다.

큰 모델이나 긴 학습이 필요하면 같은 로봇에서 작은 데이터, 짧은 실험, 축소된 방법을 제안할 수 있다. 원문 핵심을 유지하지 못하는 축소라면 해당 현상을 설명할 수 없다고 표시한다.

## 4. 학습 메모

메모는 한 논문 안에서만 사용하며, 별도 개념 데이터베이스를 만들지 않는다. 각 항목에는 개념, 상태, 판단의 짧은 근거를 둔다.

| 관찰 | 기록 | 다음 턴 반영 |
|---|---|---|
| 예상 질문을 건너뜀 | 미확인 | 필요하면 짧게 확인하거나 설명을 제공한다. 진행을 막지 않는다. |
| 예상 또는 이유에 구체적인 오류가 있음 | 혼동 관찰 | 해당 차이가 드러나는 설명이나 비교 실험을 우선한다. |
| 새 조건의 결과와 이유를 설명함 | 이해 근거 있음 | 같은 기초 설명을 반복하지 않고 다음 개념으로 이어간다. |
| 사용자가 메모를 정정함 | 사용자 정정임을 명시 | 다음 턴부터 반영한다. 자기 보고를 검증된 정답으로 바꾸지 않는다. |

전체 논문에 대한 `완벽히 이해함`을 자동 판정하지 않는다. 실험 완료, 코스 진행, 개념 이해의 근거를 구분한다.

## 5. 성공과 실패를 확인하는 장면

1. 분석된 논문에서 실험 탭을 열면 시작 버튼과 기존 기록이 보인다. 시작 전에는 새 자료 수집이나 AI 생성이 발생하지 않는다.
2. 시작 후 설명과 학습 순서가 먼저 나타나고, 근거가 연결된 해당 로봇의 첫 실험을 실행할 수 있다.
3. 가정 확인 대기 중에는 관련 계산을 실행하지 않는다. 확인한 가정이 바뀌면 이전 확인을 재사용하지 않는다.
4. 사용자가 예상을 건너뛰어도 실행하며, 미확인 기록을 다음 질문의 문맥에 반영한다.
5. 자연어 변경으로 파라미터뿐 아니라 핵심 구성 요소 하나를 바꾸고, 같은 초기 조건에서 기준 결과와 비교한다.
6. 잘못 생성된 수정안이 실패해도 이전에 검증된 실험을 다시 열 수 있다.
7. 5분 준비 한도를 넘기면 이유와 설명을 남기고 추가 자동 시도를 하지 않는다. 늦게 도착한 응답이 실패 상태를 준비 완료로 덮어쓰지 않는다.
8. 앱을 다시 열어도 같은 논문의 메모가 남는다. 다른 논문에 해당 메모가 들어가지 않는다.
9. 실제 계산 결과의 값 하나 이상을 화면 표시와 대조한다. 같은 설정과 시드의 재실행, 시간 간격을 줄인 계산을 비교한다.

## 6. 확정되지 않은 실측값

- 첫 실험 5분, 첫 핵심 학습 20분은 목표다. 현재 코드에서 달성했다고 주장하지 않는다.
- 지원 가능한 로봇 자료 형식과 플랫폼별 성능은 첫 기술 검증에서 측정한다.
- 사용자 확인에 걸린 대기 시간과 실제 준비 계산 시간을 구분해 기록한다. 벽시계 총 대기 시간을 숨기지 않는다.
- 자동 자료 탐색과 실행 준비가 모든 로보틱스 논문에서 성공한다고 보장하지 않는다. 실패를 정직하게 보여주는 경로도 필수 산출물이다.

## 7. 이후 범위

바이오, ML, 광학에 대한 검증 확대와 가설 설계, 반복 실험, 논문 간 방법 비교는 장기 방향이다. 첫 구현에서 범용 플러그인 계층이나 여러 실행 엔진을 미리 만들지 않는다.
