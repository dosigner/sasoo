# 사수와 토의 설계

작성일: 2026-10-09 (결정 기간 2026-10-07 ~ 2026-10-09)

상태: 결정 완료, 구현 전. 결정 과정과 근거 원문은 로컬 지도 `.scratch/discussion/map.md`와 그 티켓 00~06에 있다. 프로토타입과 말투 실측 하네스는 브랜치 `prototype/discussion-context`(main에 병합하지 않음), 맥락 예산 조사는 `RESEARCH/2026-10-07-chat-context-budget.md`에 있다. 용어는 저장소 루트 `CONTEXT.md`의 "토의" 절을 따른다.

## 1. 목표와 범위

워크벤치의 플로팅 채팅 카드(`sasoo/frontend/src/components/ChatPanel.tsx`)를 "사수와 토의"로 바꾼다. 사용자가 논문 해석이나 실험 아이디어를 내면, 사수가 그 논문의 근거(페이지, 그림, 표, 절)로 맞는 부분을 먼저 짚고 근거가 약한 곳에서만 반론하고 되묻는다. 단순한 질문에는 바로 답한다.

| 요구사항 | 완료를 관찰하는 방법 |
|---|---|
| R1. 확인 우선 말투 | 해석이나 주장에 대한 답의 첫 문장이 논문이 뒷받침하는 범위를 근거 위치와 함께 인정하거나, 정반대일 때 다르다고 분명히 말한다. |
| R2. 상대는 사수 하나 | 화면의 상대 이름이 "사수"이고, 분야 에이전트는 카드 부제의 분야 표시로만 보인다. |
| R3. 토의 기록 | 논문을 다시 열거나 앱을 재시작해도 토의가 이어서 보인다. 끊긴 답은 "중단됨"으로 남는다. |
| R4. 맥락의 가시성 | 입력창 위 막대에서 사수가 이번에 보는 입력 토큰과 예산 260K를 보고, 누르면 출처별 토큰과 잘림을 본다. |
| R5. 맥락 초기화와 삭제의 구분 | "새 맥락"은 기록을 남기고 그 이후만 사수에게 보낸다. 토의 삭제는 메뉴 안에서 확인 대화상자를 거쳐 기록을 지운다. |
| R6. 정직한 자르기 | 메시지 개수로 몰래 자르지 않는다. 예산을 넘기 전에 자동 맥락 초기화가 이유와 함께 구분선으로 보인다. |

범위 밖: 에이전트끼리의 토론(옹호 측과 비판 측의 논쟁, 별도 지도), 성격별 에이전트, 토의 원문의 보고서 내보내기, 질문과 토의를 나누는 모드.

## 2. 지켜야 할 기존 계약

- 채팅 카드는 닫힘 애니메이션의 `animationend`에서 언마운트한다. `animation: none`으로 우회하지 않는다.
- 추천 질문은 입력창만 채우고 바로 보내지 않는다.
- 섹션 전환 효과는 opacity만 쓴다.
- DEC-022: role별 프로바이더 오버라이드를 두지 않는다. 말투 게이트에 미달한 프로바이더를 다른 프로바이더로 돌리지 않고 문구를 고친다.
- Quiet Minimal 칩 어휘와 굵기 잠금(2026-08-04 계약)을 따른다.

## 3. 용어

`CONTEXT.md`의 "토의" 절이 기준이다. 요약하면 다음과 같다.

- **토의**: 사용자와 사수의 1:1 대화. 논문 하나에 묶인다. "채팅", "질문 도우미", "토론"이라 부르지 않는다.
- **사수**: 토의의 상대. 분야 에이전트는 사수의 전문 분야 표시다.
- **맥락**: 사수가 한 번 답할 때 보는 범위(논문 원문, 분석 단계 결과, 마지막 맥락 초기화 이후의 대화).
- **맥락 초기화**: 기록은 화면에 두고 그 이전의 대화를 사수에게 보내지 않게 나누는 구분. 사용자가 넣거나, 재분석이 끝났을 때와 예산을 넘을 때 자동으로 들어간다.
- **토의 기록**: 논문 하나에 하나. 논문 삭제와 함께 지워지고 내보내기에 들어가지 않는다.
- **맥락 예산**: 한 번에 보내는 입력의 토큰 상한, 260K.
- **토의 삭제**: 기록 자체를 지우는 것. 되돌릴 수 없다.

## 4. 사수의 말투

채팅 system prompt는 서비스 규칙(`_SYSTEM_INSTRUCTION_KO`), 페르소나, 행동 규칙 문단, 논문 맥락 순으로 조립된다(`sasoo/backend/api/analysis_routes.py:1313`). 행동 규칙 문단을 아래 문구로 바꾼다(티켓 04의 P3에 비판 강도 규칙 한 줄을 더한 것).

```
아래는 이 논문의 분석 결과야. 너는 사용자와 이 논문을 두고 토의하는 사수야.
- 사용자가 해석이나 주장을 말하면, 첫 문장에서 논문이 실제로 뒷받침하는 범위를 근거와 함께 먼저 인정해. 과장되거나 일부만 맞는 주장도 마찬가지로, '아니'나 '전혀 달라'로 시작하지 말고 첫 문장을 논문이 실제로 보인 범위로 시작해. 넘어선 부분은 둘째 문장부터 짚어.
- 사용자의 말이 논문과 정반대면 첫 문장에서 다르다고 분명히 말하고, 논문이 실제로 한 것을 근거와 함께 알려줘.
- 근거 위치는 논문의 페이지, 그림, 표, 절로 적어. '분석 결과'를 출처로 쓰지 마. 위치를 모르면 위치를 지어내지 마.
- 되물을 때는 사용자의 의도나 조건이 답을 바꿀 때만 한 가지를 물어.
- 단순한 질문(기호 뜻, 값 확인)에는 반론 없이 바로 답해.
- 사용자가 더 비판적으로 따져 달라고 하면, 근거가 있는 범위 안에서 반론을 먼저 말해.
- 실험 아이디어에는 논문 조건과 달라지는 점을 먼저 확인할 항목으로 짚되, 다섯 항목을 넘기지 마.
- 논문 밖의 이야기에는 짧게 답하고 논문으로 돌아와.
- 근거가 맥락에 없으면 지어내지 말고 확인할 수 없다고 말해. 추측은 추측이라고 밝혀.
```

1단계 게이트(2026-10-09, 두 프로바이더 84회, [검증 기록](../../validation/2026-10-09-discussion-stage1-tone-gate.md))에서 처음 문구는 과장 주장 선인정이 OpenAI 2/6, Gemini 3/6으로 미달해 위 문장으로 고쳤고, 고친 문구는 6/6, 6/6으로 통과했다. 그 전의 실측 근거(2026-10-08, gpt-6-luna effort low, 발화마다 1회, 총 48회 $0.0152): P3는 판정 정확 12/12, 근거 위치 인용 9/12(현재 문구 0/12), 단순 질문 반론 0/4, 이상 표현 0건이었다. 알려진 빈틈은 과장 주장 선인정 1/2, 인용 쪽수의 PDF 대조 미검증, 비결정성 미확인이다. 비판 강도 규칙 한 줄은 1단계 게이트에서 처음 측정했다(비판 요청 6/6에서 근거 없는 반론 0).

주의: 페르소나에는 에이전트의 `personality`가 그대로 들어간다(예: 사용자 정의 channel의 "가차없이 지적함"). 성격 문구가 확인 우선 규칙과 충돌할 수 있으므로, 게이트 논문 2편은 서로 다른 에이전트를 거치게 고른다.

## 5. 화면

플로팅 카드를 유지한다(폭 26rem). 사수 답의 그림 칩을 누르면 분석 패널이 그림 탭으로 바뀌므로, 탭으로 옮기면 토의가 화면에서 사라지기 때문이다. 런처와 카드 헤더에는 사수 오브를 쓴다(v1.0.2, PR #110로 출시됨).

- **헤더**: 제목 "사수", 부제는 담당 에이전트의 `domain_display`(영어, 예: "Optics & Photonics"). 전문 사수가 없는 분야는 OpenAlex 영문 대분야명(예: "Materials Science", `.scratch/field-taxonomy/map.md`). 헤더에는 맥락 표시를 두지 않는다.
- **맥락 막대**(2단계): 입력창 바로 위. "맥락 21.6K / 260K 토큰" 형식과 오른쪽의 "새 맥락" 텍스트 버튼. 막대를 누르면 대화를 가리지 않는 작은 팝오버로 출처별 토큰(논문 원문, 분석 단계별, 대화)과 잘림을 보인다. 카드 전체를 덮는 시트는 쓰지 않는다.
- **맥락 초기화 구분선**(2단계): 이유와 시각을 담은 안내 상자. 이유는 "새 맥락", "재분석이 끝나 새로 시작", "맥락 예산을 넘어 새로 시작" 세 가지다. 초기화 이전 대화는 기본으로 접고("이전 맥락의 대화 n개 보기"), 펼치면 맥락 밖 메시지를 흐리게 보인다.
- **토의 삭제**(2단계): 더보기 메뉴에서 열고, 카드 안의 확인 대화상자로 확정한다.
- **문자열 교체**(1단계):

| 지금 | 바뀐 뒤 |
|---|---|
| 카드 제목 "셀 에이전트" 등 `display_name_ko` | "사수", 부제 `domain_display` |
| "질문 도우미 열기" | "사수와 토의하기" |
| "질문 도우미 닫기" | "토의 닫기" |
| "질문 도우미를 준비하고 있어요" | "사수가 논문을 읽고 있어요" |
| "핵심 주장과 질문 도우미가 열려요" | "핵심 주장과 토의가 열려요" |
| "질문 도우미 답변 한 번과 비슷한 비용" | "사수 답변 한 번과 비슷한 비용" |
| "담당 에이전트", "다른 에이전트로 넘기세요" | "담당 분야", "다른 분야로 넘기세요" |
| "에이전트 채팅 패널을 준비하고 있어요" | "토의 카드를 준비하고 있어요" |
| "대화 초기화" 버튼 | "토의 삭제"(1단계는 이름만, 동작은 그대로) |

에이전트 이름과 분야의 화면 표시는 영어(`display_name`, `domain_display`)로 바꾼다. 쓰는 곳은 `ChatPanel.tsx`, `RecentPaperRow.tsx`, `WorkbenchHeader.tsx`, `workbenchSummaries.ts`, `Workbench.tsx`다. frontmatter의 `_ko` 필드는 지우지 않고, 프롬프트의 페르소나 값도 바꾸지 않는다. 백엔드 에이전트 정의, 분석 결과 마크다운의 "에이전트" 라벨, 코드 주석은 그대로 둔다.

## 6. 토의 기록 저장(2단계)

- 단위: 논문당 토의 하나. 주제는 맥락 초기화로 나눈다. 카드 안에 토의 목록을 두지 않는다.
- 위치: SQLite 새 테이블, `papers` 참조 `ON DELETE CASCADE`. 선례는 `experiment_plans`. 기존 테이블은 바꾸지 않는다. 스키마는 구현 단계에서 다시 승인받는다.
- 질문은 보낸 즉시 저장한다. 중지, 오류, 앱 종료로 끊긴 답은 받은 데까지 "중단됨"으로 남기고, 맥락으로 보낼 때는 뺀다.
- 재분석이 끝나면 기록은 그대로 두고 맥락 초기화를 자동으로 넣는다.
- 논문 삭제(지연 삭제와 되돌리기 범위 안)와 함께 지워진다. 보고서 내보내기에 넣지 않는다.
- 맥락 초기화와 자르기는 백엔드가 지킨다. 지금 채팅 API는 상태가 없고 프런트가 매번 대화 전체를 보낸다. 2단계에서 서버가 기록을 가지므로 이 계약이 바뀐다.

## 7. 맥락 예산과 자르기(2단계)

- 예산: 두 프로바이더 모두 260K 토큰. gpt-6-luna는 입력 272K를 넘으면 요청 전체에 입력 2배, 출력 1.5배 할증이 붙으므로 그 바로 아래로 맞췄다. 한 턴 입력 최악값은 Gemini 약 $0.195, Luna 약 $0.026(정가 계산값, 캐시 미반영)이다.
- 메시지 개수 상한 `history[-20:]`(`analysis_routes.py:1327`)을 없앤다.
- 새 질문을 보내기 전에 예산을 넘는지 판정하고, 넘으면 맥락 초기화를 자동으로 넣는다. 새 질문은 새 맥락의 첫 메시지가 된다.
- 세는 방법: 평소에는 직전 응답의 실제 과금 입력 토큰에 새 질문의 추정값(한국어 1자를 1토큰으로 보는 보수적 추정)을 더한다. 이 합이 234K(예산의 90%)를 넘을 때만 실제로 보낼 요청 그대로를 프로바이더 계산 API(Gemini `countTokens`, OpenAI `POST /v1/responses/input_tokens`)로 센다. 답을 받은 뒤에는 실제 usage로 막대를 갱신한다.
- 측정 기준점: 히스토리 없는 첫 턴 입력은 6,712~7,403 토큰(gpt-6-luna usage, 2026-10-08 측정)으로 예산의 약 2.8%다. 자동 초기화는 아주 긴 토의에서만 일어난다.

## 8. 출시 단계

### 1단계 "말투와 이름" (v1.0.3, PR 1개)

범위: 4장의 행동 규칙 문단, 5장의 문자열 교체와 영어 표시, 읽기 안내 고아 데이터 수정. 논문을 삭제해도 IndexedDB의 읽기 안내가 남는 결함은, 모든 삭제가 지나는 `usePapers.deletePaper`(`sasoo/frontend/src/hooks/usePapers.ts:173`)에서 서버 삭제가 성공한 직후 `deleteGuide(id)`를 부르는 것으로 고친다(실패해도 삭제는 막지 않는다). 기존 진입점(PDF 선택의 "이 부분 설명", 후속 칩, 추천 질문)은 동작을 그대로 두고 문구만 바꾼다. `history[-20:]`도 유지한다.

게이트: 논문 2편 x 발화 7종(맞는 해석, 과장된 해석, 틀린 해석, 실험 아이디어, 기호 질문, 잡담, "이 해석을 비판적으로 따져 줘") x 3회를 두 프로바이더에서 돌린다(84회, 예상 약 $0.3, 계산값). 프로바이더별 통과 기준은 다음과 같다.

| 지표 | 기준 |
|---|---|
| 판정 정확 | 42/42 |
| 근거 위치 인용 포함 | 32/42 이상(75%) |
| 단순 질문과 잡담에 반론 | 0/12 |
| 과장 주장에서 맞는 범위 먼저 | 4/6 이상 |
| 비판 요청에서 근거 없는 반론 | 0/6 |

### 2단계 "기록과 맥락" (v1.1.0, PR 2개)

## 9. 미검증과 열린 위험

- 1단계 게이트(2026-10-09)는 단일 턴, 발화마다 3회, 논문 2편이다. 다른 분야 논문과 다중 턴에서의 말투는 아직 모른다. 인용 위치는 표본 10건만 PDF와 대조했다.
- OpenAI `input_tokens`의 비용, 레이트 리밋, 지연을 모른다.
- 글자 수를 토큰 수로 보는 추정은 영어와 코드에서는 실제보다 크게 나오지만, 이모지나 드문 한자처럼 한 글자가 여러 토큰이 되는 입력에서는 작게 나올 수 있다. 다만 추정 대상은 새 질문 하나뿐이고 나머지는 직전 usage 실측값이라, 오차의 폭은 질문 길이를 넘지 않는다. 2단계 테스트에서 실제 usage와 추정의 비를 기록한다.
