## 0. 한 줄 요약

**착수 전에 정답 기준부터 다시 세워야 한다.** 현재 알려진 "총 절대오차 33"은 두 겹으로 틀렸다 —

## 1. 착수 전에 확정된 사실

### 1.1 정답 기준이 로마 숫자를 놓친다 (직접 검증 완료)

`TABLE_LABEL_PATTERN`이 `document_manifest.py:18`과 `table_resolver.py:22` 양쪽에서
`^\s*(?:Table|Tbl\.?)\s*(\d+[A-Za-z]?)\b` — **digit only**다. IEEE 계열은 로마 숫자를 쓴다.

PDF 텍스트 블록 문두 기준 실측:

| 논문 | 로마 라벨 | 아라비아 |
|---|---|---|
| 2017_COMST_OpticalComm | **8** (`Table I`~`Table VIII`) | 0 |
| 2013_IEEETIP_ClusterCoSaliency | **1** (`Table I`) | 0 |
| 나머지 10편 | 0 | 각 0~5 |

즉 "정답 0"이라고 봤던 두 논문의 실제 표는 8개와 1개다. 더 나쁜 것은 **정답 기준 두 가지가
독립이 아니었다는 점**이다 — 캡션 집계와 본문 언급 집계가 같은 digit-only 정규식을 공유하므로
같은 맹점을 갖는다. "두 기준이 11/12에서 수렴하니 신뢰할 만하다"는 판단은 무효다.

### 1.2 과추출의 지배적 원인은 검출기 오탐이 아니라 캡션 게이트 부재 (직접 검증 완료)

그림 쪽 계약 7("캡션 없는 후보는 버린다")의 대칭 규칙이 표에는 **없다**. 캡션이 없으면
`_table_num`이 `Table {fallback_index}`로 가짜 번호를 붙여 그대로 산출물이 된다
(`table_resolver.py:116-130`).

산출된 표 38개 중 **28개가 `caption=None`**이고, 이 비율이 정확도와 거의 완벽히 상관한다:

| 논문 | 산출 | caption=None | 상태 |
|---|---|---|---|
| 2017_COMST | 9 | **9 (전부)** | 과추출 |
| 2026_SR_Agile | 4 | **4 (전부)** | 과추출 |
| 2025_TurboQuant | 4 | **4 (전부)** | 과추출 |
| 2014_Saliency | 12 | 9 | 과추출 |
| TurPy_OpticTurb | 2 | 1 | 과추출 |
| 2013_IEEETIP | 1 | 1 | 가짜(우연히 개수만 일치) |
| **2022_SciRep** | 3 | **0** | ✅ 정확 |
| **2025_OptExpress** | 3 | **0** | ✅ 정확 |

### 1.3 "누락 −6"은 측정 아티팩트일 가능성이 매우 높다 (코드로 확정)

인수인계 §5 하네스는 `os.environ.pop("GEMINI_API_KEY")`로 VLM을 끈다. 그림 경로는 휴리스틱만으로
정답이 나와 문제가 없었지만, **표 경로는 격자 복원이 본질적으로 VLM에 의존**한다:

1. `caption_fallback_crop` 후보는 `text_grid=[]`로 생성된다 (`table_candidates.py:334-368`).
   주석: "이 폴백은 'VLM에게 볼 기회를 준다'까지가 역할이고, 실제 격자 복원은 resolver 몫이다."
2. 키가 없으면 `_repair_with_vlm`이 그 빈 grid를 그대로 반환한다 (`table_resolver.py:173-174`).
3. 3단계의 `if not _has_meaningful_grid(grid): ... continue`에서 **구조적으로 100% 탈락**한다
   (`table_resolver.py:~332`).

실측이 정확히 이 예측과 일치한다 — 후보가 캡션 폴백 뿐인 OptFor(6개)와 2022_ApplOpt(1개)만
전멸했고, `hybrid`가 섞인 2022_SciRep(폴백 3 + hybrid 3)은 3/3 성공했다.

**키를 넣고 재측정하기 전까지 이것을 제품 버그로 취급하면 안 된다.**

### 1.4 캡션 게이트의 안전성 — 직접 검증 완료

캡션 게이트의 최대 리스크는 "캡션 연결에 실패한 **진짜** 표까지 죽이는 것"이다. 현재 코드로
후보별 `best_caption_id`를 실측했다:

**2025_TurboQuant (정답 2) — 안전하다.**
```
캡션(kind=="table") 3개: p20 'Table 1: LongBench-V1...' ×2(중복), p20 'Table 2: Quantization time...'
후보 p18 pdfplumber            cap=None     ← 오탐
후보 p18 pdfplumber            cap=None     ← 오탐
후보 p20 caption_fallback_crop cap=cap:p20:n0  ← 진짜, 캡션 연결 OK
후보 p20 caption_fallback_crop cap=cap:p20:n1  ← 진짜, 캡션 연결 OK
후보 p20 caption_fallback_crop cap=cap:p20:n2  ← 진짜, 캡션 연결 OK
후보 p21 pdfplumber ×3         cap=None     ← 오탐
```
캡션 연결은 **성공하고 있다.** 산출된 4개가 전부 `caption=None`이었던 것은 진짜 후보(p20)가
VLM 부재로 죽고 오탐(p18·p21)만 살아남았기 때문이다. 게이트는 오탐만 걷어낸다.
(단 `Table 1` 캡션이 2개로 중복돼 있어 `Table 1 [2]` 위험이 있다 → 단계 4의 근거.)

**2017_COMST (정답 8) — 로마 지원 없이는 전멸한다.**
```
캡션(kind=="table") 0개          ← 로마 숫자라 _caption_kind가 인정하지 않음
후보 9개 전부                     cap=None
```
**로마 지원 없이 게이트를 걸면 9 → 0이 되어 정답 8을 통째로 잃는다.**
§2의 "0단계가 1단계보다 반드시 먼저"라는 순서 논리가 이것으로 실증됐다.

## 2. 작업 순서와 근거

| 단계 | 내용 | 기대 효과 |
|---|---|---|
| **S0** | 정답 기준 재수립 + `table_gold.json` 고정 | 허수 오차 ~10 제거, 이후 모든 측정의 기준 |
| **S1** | 측정 하네스(그림+표 통합, VLM 2-lane) | 진행 상황을 볼 수 있게 됨 |
| **0** | 로마 숫자 라벨 지원 | 캡션 게이트의 **선결 조건** |
| **S2** | 과추출 후보 포렌식(크롭 육안) | 원인 확정 |
| **1** | 캡션 필수 게이트 + 캡션 단위 중복제거 | 과추출 대부분 제거 |
| **S3** | VLM 켠 상태의 폴백 성공률 측정 | 누락의 실재 여부 판정 |
| **2** | (실재할 경우에만) 폴백 생존 경로 + 안전망 | 누락 해결 |

**왜 이 순서인가 — 간섭이 한 방향으로만 존재한다.**

- **0단계는 1단계보다 반드시 먼저**다. 로마 숫자를 인식하지 못하면 `_caption_kind`가
  `Table I ...`를 캡션으로 인정하지 않아(`document_manifest.py:596-598`), 캡션 필수 게이트가
  **2017_COMST의 진짜 표 8개를 전부 죽인다.** 선택이 아니라 필수 순서다.
- **1단계가 2단계를 방해하지 않는다.** 캡션 필수 게이트는 캡션 *없는* 후보만 죽이는데,
  `caption_fallback_crop`은 정의상 `best_caption_id`를 갖는다(`table_candidates.py:353-367`).
- **반대 방향으로는 방해한다.** 누락을 고치는 자연스러운 수단(VLM 게이트 완화,
  `_is_plausible_table_bbox` 완화)은 캡션 없는 pdfplumber 후보까지 살려 과추출을 키운다.

## 3. 측정 지표 — 개수에서 라벨 집합으로

개수 비교는 2017_COMST(gold `Table I~VIII` 8개 vs 추출 `Table 1~9` 9개, 캡션 연결 0개)를
"오차 1"로 통과시킨다. 실제로는 라벨이 전부 가짜다. 지표를 셋으로 바꾼다:

```
FP = extracted_labels - gold_labels
FN = gold_labels - extracted_labels
오차 = |FP| + |FN|
정확일치 = extracted_labels == gold_labels
캡션연결률 = (caption is not None인 표) / (전체 산출 표)
```

로마→아라비아 정규화를 하면 라벨 집합이 **우연히** 맞아버리므로(2017: gold{1..8} vs 추출{1..9}),
**캡션 연결률을 독립 지표로 반드시 함께 본다.** 캡션 연결률 100%가 아니면 라벨이 맞아도
통과로 치지 않는다.

`table_gold.json`은 개수가 아니라 **증거를 동반한 라벨 집합**으로 고정한다:

```json
{
  "2017_COMST_OpticalComm_optical_communications": {
    "labels": ["Table I", "Table II", "..."],
    "evidence": [{"label": "Table I", "page": 4, "caption": "TABLE I  COMPARISON OF ..."}]
  }
}
```

## 4. 진단 절차 (코드 수정 전)

### S0 — 정답 라벨 전수 수집 및 확정

3개 소스에서 라벨 집합을 뽑아 교차한다:

- **(A) PDF 텍스트 블록**: `recover_missing_caption_blocks`와 동일하게 PyMuPDF `get_text("blocks")`
  → `strip_caption_decoration` → NFKC → **확장 라벨 정규식**
  `(?:TABLE|Table|Tbl\.?)\s*(\d{1,2}[A-Za-z]?|[IVXLC]{1,6})\b` → `_label_is_followed_by_caption_body`로
  본문 언급 배제
- **(B) markdown 본문 언급**: 같은 확장 정규식
- **(C) 매니페스트 `captions` + `pages[].caption_blocks`**

세 소스가 일치하는 논문은 자동 확정, 하나라도 어긋나면 **PDF를 렌더해 눈으로 확인**한다.
결과를 `docs/table_gold.json`으로 커밋해 회귀 기준으로 고정한다.

**이미 알려진 어긋남 — 2014_Saliency**: 캡션이 표 본문과 같은 텍스트 블록에 병합돼 있어
(A)가 0을 낸다(p4 블록이 `Benchmark Boundary Connectivity Geodesic Saliency Precision Recall ...`로
시작). markdown에는 `Table 1. Background...`, `Table 2. Comparison...`이 둘 다 있다.
**gold = {Table 1, Table 2}로 확정하되, 페이지 렌더 육안 승인을 거친다.**

### S1 — 측정 하네스 (상시 사용)

인수인계 §5 그림 스크립트를 확장한다. 요건 4가지:

1. **그림과 표를 같은 실행에서 함께 출력한다.** 로마 확장은 `_caption_kind`를 건드리므로
   그림 12편 정확일치가 깨질 수 있다. 매번 같이 봐야 한다.
2. **두 lane을 나란히 기록한다.**
   - *결정적 lane* (키 없음): pdfplumber FP 수, **gold 캡션별 후보 재현율**, 캡션 소유권 중복,
     폴백 후보 생성 여부 — VLM 비결정성 없이 재현 가능한 진단
   - *프로덕션 lane* (키 있음): 최종 FP/FN, 폴백 성공률, VLM 호출 수와 실패 이유
3. `if k: c["kind"] = k` 함정 회피 — 반드시 `_caption_kind(...) or "unknown"`
   (그림 작업에서 실제로 걸렸던 함정. 인수인계 §3 참조).
4. 개수뿐 아니라 **라벨 집합, `caption is None`, `source_kind`, `parse_method`, `confidence`**를
   함께 찍는다.

**키 확보 — `worker=True`로 호출할 것 (함정).** `GEMINI_API_KEY`는 환경변수에 없고,
`api_key_runtime.load_api_keys_from_settings(settings, worker=...)`가 DB `settings`에서 읽어
복호화 후 환경변수에 넣는다.

```python
from models.database import fetch_all
from services.api_key_runtime import load_api_keys_from_settings
rows = await fetch_all("SELECT key, value FROM settings WHERE key = 'gemini_api_key'")
await load_api_keys_from_settings({r["key"]: r["value"] for r in rows}, worker=True)
```

**`worker=False` 경로는 `async_credential_store_lock()`을 잡고 DB에 마이그레이션 UPDATE를
친다**(`api_key_runtime.py:41-75`). 측정 하네스가 사용자 DB를 건드리면 안 된다.
DB 경로는 인수인계 §1 함정대로 개발 모드(`sasoo/backend/library/sasoo.db`)인지 먼저 확인한다.

**비용·시간 — 사실상 문제가 아니다.**
- **파싱은 재호출하지 않는다.** 저장된 `.odl_manifest.json`을 재사용하므로 진짜 비싼 부분
  (gemini 페이지 파싱)은 0이다. 이게 절감의 핵심이고 이미 확보돼 있다.
- 호출 단위는 후보 1개당 `_repair_with_vlm` 1회. 12편 후보 ~70~90개 중 `needs_vlm_repair`
  ~40~55개. 회당 ~2k 토큰(이미지 ~1.3k + 텍스트 ~0.3k in, ~0.5k out) → 전 코퍼스 1회
  **10만 토큰 이내, $0.05~0.1 수준**.
- `table_resolver.py:288`이 논문 내 후보를 `asyncio.gather`로 병렬 처리하므로 논문당 5~20초,
  **전 코퍼스 3~6분**.

**캐싱은 비용이 아니라 재현성 때문에 필수다.** VLM 출력은 비결정적이라, 캐싱 없이는 수정
전후 델타가 내 수정 때문인지 VLM 흔들림 때문인지 구분할 수 없다.
- `_repair_with_vlm`을 하네스에서 monkeypatch해 디스크 캐시를 씌운다.
  키 = `sha1(pdf해시 + page_number + bbox + text_grid + 프롬프트버전)`, 값 = `(rows, model, confidence)`.
- 인수인계 §6-2 계약("`call_interaction`을 통째로 대체하지 말 것") 위반이 아니다 — 거기서 금지한
  것은 **성능 벤치마크**의 재시도·세마포어 우회이고, 여기는 정확도 측정의 결정성 확보다.
  다만 캐시 히트율을 로그로 남겨 캐시가 실제 호출을 가려버렸는지 알 수 있게 한다.
- **노이즈 바닥을 먼저 잰다**: 캐시 없이 3회 반복해 라벨 집합이 흔들리는 폭을 측정한다.
  **이 폭보다 작은 개선은 개선이라고 부르지 않는다.** 이 수치가 이후 모든 판단의 유의수준이 된다.

### S2 — 과추출 후보 포렌식

과추출 논문(2014, 2026, TurboQuant, 2017)의 `table_candidates` 전수를 덤프하고,
각 후보 bbox를 PyMuPDF로 크롭해 PNG로 저장한다.
컬럼: `page / source_kind / bbox / grid 행×열 / non_empty / has_meaningful_grid /
plausible_ruled_bbox / best_caption_id`.

**그림 작업에서 캡션 151건을 전수 분류하니 규칙이 저절로 드러난 것과 같은 절차다.**
크롭 이미지를 훑으면 오탐의 정체가 코드 추측 없이 확정된다.

### S3 — VLM 폴백 성공률 측정 (2단계 진입 전)

OptFor 6건 + 2022_ApplOpt 1건의 `caption_fallback_crop` 후보에 대해 `_repair_with_vlm`을
단건 호출하고 (a) 예외 발생 여부, (b) 반환 grid 크기를 기록한다.
**현재 코드는 예외를 통째로 삼켜(`table_resolver.py:203-204`) 실패가 조용히 빈 grid로 둔갑한다 —
진단 시엔 예외를 반드시 노출시킬 것.**

### 5.1 "VLM 없이 캡션 폴백이 죽는 것"은 고쳐야 하는가

**설계 의도대로 두되, 실패를 조용히 삼키는 것만 고친다.**

1. 표의 산출물은 `csv/html/markdown` 격자다(`table_resolver.py:355-360`). **격자 없는 표는
   그림과 달리 소비 가능한 산출물이 아니다.** 그림은 crop 이미지만으로 완결되지만 표는 아니다.
   따라서 "격자 복원이 VLM 의존"은 결함이 아니라 매체 특성이다.
2. 다만 현재는 VLM이 없거나 실패했을 때 **사용자에게 아무 신호가 없다.** 표가 통째로 사라지고
   `low_confidence_pages`에만 들어간다. 고칠 것:
   - 키 없음/예외로 반환할 때 그 사실을 후보에 기록하고, resolver가 상태로 남기거나 최소한
     **경고 로그**를 남긴다 (그림 쪽 `figure_resolver` 전멸 경고와 동형, 계약 7).
   - `except Exception`의 무음 삼킴 자체가 고칠 가치가 있다.
3. **오프라인 격자 복원기 신설은 하지 않는다.** 코퍼스에서 그게 필요한 건 OptFor 1편이고
   투입 대비 회수가 안 맞는다. 백로그로 둔다.

**측정 방법론에의 귀결**: 이후 표 측정은 **항상 VLM을 켜고** 돈다. 인수인계 §5의
`os.environ.pop("GEMINI_API_KEY")` 관행이 **그림 전용**임을 인수인계 문서에 명시해야 한다.
안 적어두면 다음 세션이 같은 함정에 빠진다 — §3의 `if k:` 함정과 정확히 같은 종류의 사고다.

## 6. 회귀 방지

1. **그림·표 동시 측정이 기본.** 로마 확장은 `TABLE_LABEL_PATTERN`·`_caption_kind`를, 캡션 게이트는
   계약 6·8을 건드린다 — 전부 그림과 공유하는 코드다. 표만 재고 넘어가면 그림 12편 정확일치가
   조용히 깨진다.
2. **표 audit 변화가 그림 재시도를 바꿀 수 있다.** `find_suspect_pages`는 `tables`/`table_candidates`를
   실제로 읽어 판정하고(계약 3), 그 결과가 그림 aggressive 재시도에도 쓰인다.
3. **핀 테스트를 먼저 깐다.** 수정 전에 현재 맞는 것을 고정하고 **수정 전에 통과하는지 확인**한다:
   2012(∅), 2019(∅), 2022_SciRep({1,2,3}), 2025_OptExpress({1,2,3}), 그림 12편 전체.
4. **신규 테스트는 구코드에서 실패를 먼저 확인한다.** 픽스처 안에 "조건이 재현되는지" 단언하는
   줄을 넣는다. 예: `assert TABLE_LABEL_PATTERN.match("Table IV ...") is None`을 구코드에서 먼저 확인.
5. **전역 임계값을 건드리지 말 것.** `_is_meaningful_grid`를 바꾸면 ODL/hybrid 참양성이 함께 탈락한다.
   필터는 pdfplumber-only 또는 캡션 유무로 국한한다.
6. **계약 6 동반 수정**: 로마 확장 시 `_table_num`도 같이 고쳐야 한다. 안 그러면 캡션은 인식하는데
   번호를 못 읽어 `Table {index}`로 떨어진다.
7. `pytest -q` 441 passed 유지.

## 8.1 검토했으나 기각한 안

1. **캡션 게이트를 `build_table_candidates`에 넣기** — `document_audit`이 `table_candidates`를
   직접 읽어 suspect page를 판정하고(계약 3, `document_audit.py:109-114`), 그게 다시
   `_repair_reasons`의 `page_audit_suspect`(`table_resolver.py:110-111`)를 통해 VLM 게이트를
   바꾼다. 변수를 하나씩 움직일 수 없게 되므로 기각. **게이트는 `table_resolver`의 방출 시점에
   넣는다** — 그러면 audit 입력이 불변이다.
2. **VLM 없이도 격자를 복원하는 오프라인 폴백 신설** — §5.1의 이유로 백로그.
3. **pdfplumber `table_settings` 튜닝을 먼저** — 정답 기준이 틀린 상태(로마 숫자)에서
   하이퍼파라미터를 맞추면 잘못된 목표에 과적합된다. 단계 5로 미룸.
4. **프롬프트 강화로 VLM 수리율 올리기를 1순위로** — 인수인계 §4의 교훈: 확률적 실패를
   프롬프트로 막지 않는다. 다만 표는 그림과 달리 결정적 대체 경로가 없으므로, H2b/H2c에서
   **프롬프트가 아니라 입력(크롭 이미지)을 고치는** 쪽을 우선한다.
5. **캡션 없는 표를 "무명 표"로 유지하되 UI에서 숨기기** — 파일 쓰기(`table_resolver.py:358-360`)와
   번호 충돌이 남고, `Table 1`이라는 가짜 이름이 DB에 남아 이후 모든 지표를 오염시킨다.

## 9. 두 자문의 수렴/분기 (판단 근거 기록)

deep-reasoner(Opus)와 Codex에 같은 문제를 독립적으로 맡겼다.

- 누락 −6은 `GEMINI_API_KEY` 부재로 인한 측정 아티팩트일 가능성이 높다 (양쪽이 같은 코드 경로를
