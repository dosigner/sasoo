# Sasoo 브랜치 통합 실행 계획서 — feature/gui-redesign(A) + interactions-api-ux-redesign(B)

## 결론

**A(`origin/feature/gui-redesign`, a4d56fb)를 베이스로 통합 브랜치를 만들고, B를 1회 머지한 뒤 후속 커밋 5개 묶음으로 재이식 작업을 얹는다.** B rebase는 기각. 전체 8단계, 규모 합계는 L 2건 + M 3건 + S 3건. 시작 전에 제품 결정 3건을 사용자에게 먼저 받아야 한다(아래 §2).

계획 작성 중 실측으로 확인한 사실 (조사 결과에 추가되는 것):

- **B의 tip이 조사 시점보다 1커밋 전진했다.** 조사는 2baf5e9 기준이었으나 현재 tip은 **e2df87e** ("fix(llm): guarantee SSE done event and cover chat error path", 총 28커밋 동일). 이 커밋이 채팅 SSE 에러 경로를 건드리므로 **충돌 실측(19파일/67 hunk)은 1단계에서 재측정**해야 한다. 미검증.
- interactions_client.py의 `run_in_executor(None, ...)`은 조사에 나온 2곳이 아니라 **3곳**이다: `:93`(_sync_call), `:170`(_sync_stream), **`:239`(_sync_upload — PDF files upload)**.
- A의 concurrency.py 심볼 확정: `CHAT_EXECUTOR`(4), `PIPELINE_EXECUTOR`(max(4, min(16, cpu))), `PIPELINE_LLM_SEM = asyncio.Semaphore(4)`, `RENDER_SEM = asyncio.Semaphore(3)`, `run_pipeline_blocking()`, `run_chat_blocking()`. **세마포어가 asyncio 타입이므로 B의 async 호출부에서 그대로 쓸 수 있다.**
- A의 v2 토큰 실명 확정: CSS 변수는 `--bg --surface --surface-hover --border --fg --fg-secondary --fg-muted --accent --accent-hover --accent-fg --danger --warning --success`이고 **값이 RGB 채널("228 228 231")이다. `var(--border)`를 색으로 직접 쓰면 안 되고 `rgb(var(--border) / a)` 형태여야 한다** — B CSS 이식 시의 함정. Tailwind darkMode는 `'class'`.
- 백엔드 엔트리는 `sasoo/backend/main.py` (FastAPI). `python -c "import main"`이 전 라우터를 로드하므로 import 무결성 게이트로 쓸 수 있다.
- 로컬 `feature/gui-redesign` == origin (0/0 divergence). paperbanana는 B의 analysis_routes.py에서 import 2건(:32, :86)뿐 아니라 **시각화 tool enum(:675)과 프롬프트(:1327-1329)에도 박혀 있다** — 폐기 결정 시 제거 범위가 import 한 줄이 아니다.

- Settings의 해당 섹션은 제거하고 새 페이지로 링크만 남긴다(중복 입력 방지).

## 2. 제품 결정 — 사용자에게 물을 질문 (0단계, 엔지니어링 착수 전)

**Q1. 이미지 일러스트 생성을 paperbanana로 갈 것인가, A의 대체 경로로 갈 것인가?**
- A는 paperbanana_bridge.py와 requirements 줄을 삭제하고 image_provider/image_quality 설정 + calc_image_cost를 갖춘 자체 경로(services/viz/figure_gen.py)로 대체했다. B는 paperbanana를 실사용 중(analysis_routes.py:32,86,675,1327-1329 / settings.py:446-501).
- 선택지: **1) A 노선(폐기)** — B 측 코드에서 paperbanana 분기·프롬프트·디버그 엔드포인트 제거(작업 +S). **2) B 노선(유지)** — paperbanana_bridge.py + requirements 줄 복원, A의 figure_gen과의 관계(공존/대체) 추가 결정 필요(작업 +M).
- 미결정 시 임시 기본값: **복원(유지)**. 이유: 복원 누락은 런타임 ImportError, 복원 후 삭제는 언제든 쉬움. 단 7단계 전 확정 필수.

**Q2. "AI 에이전트 생성" 기능을 유지할 것인가?**
- B의 read-only api/agents.py 재작성이 무충돌로 승리하면 A가 실사용하는 AgentGenerator(services/agents/generator.py)가 기능째 실종된다(에러 없이).
- 선택지: **1) 폐기(B 노선)** — 기능 제거를 명시적으로 승인. **2) 유지** — generator.py 복원 + B의 read-only agents.py에 generate 엔드포인트 재통합(작업 +M).

**Q3. Agents 페이지를 없앨 것인가?**
- B는 라우트/네비/lazy import 제거 + api.ts CRUD 8종 삭제. A의 변경은 스타일·문구뿐(고유 로직 0건)이라 제거 채택 시 손실이 적다.
- 선택지: **1) 제거(B 노선)**. **2) 유지** — App.tsx 라우트 복원 + CRUD 8종 복원(작업 +M).
- **제약: Q2=유지 & Q3=제거 조합은 성립하지 않는다** (생성 기능의 UI 진입점이 사라짐). Q2=유지면 Q3=유지이거나 다른 진입점 설계가 필요하다.
