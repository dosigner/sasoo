# Rust M1 공통 기준점 (2026-11-16)

Phase 16의 FigureExplain 합성 코어와 Phase 17의 실제 TCP GET /api/papers gate를 완료한 뒤, 두 세션이 같은 Git 기준점에서 작업할 수 있도록 현재 Rust와 fixture를 별도 worktree에 고정했다. Electron 기본값은 Python이다. 이 기록은 M1 전체 완료나 운영 전환 승인이 아니다.

## 포함 범위와 보존

- backend-rust 440개 파일 전체와 contract-fixtures 41개 파일을 보존했다. Rust vendor 원문, 최소 patch, provenance, font license도 포함한다.
- 기존 Rust 검사에 필요한 evaluate-pdf-engines.py와 verify-rust-pdf-resources.js를 함께 넣었다. 준비된 runtime/model/논문 PDF, 사용자 DB/library/credential, target binary는 넣지 않았다.
- Rust 1.94.1 pin, 기준 구현 계획, M1 분담 계획, 현재 main의 검증/릴리스 계획에 §6 backlog를 포함한다. Git 부모는 c70bc9de0e22844add7bee54e535698360d4599d다.
- 원래 공유 checkout의 HEAD, index와 Python/UI 수정은 바꾸지 않았다. 통합은 별도 baseline branch에서 했고 이후 작업도 별도 branch/worktree를 사용한다.
- 마지막 검증 이후 들어온 PDF process 변경과 추가 4파일 delta와 마지막 조기 dispatch I/O 실패 기록 보완 3파일을 보존해 통합했다. 원격 main의 기존 검증/릴리스 계획을 짧은 로컬 보조 문서로 대체하지 않고 기존 내용에 backlog만 추가했다.
- 원래 계약 fixture 40개(기존 39개와 OpenAPI snapshot)는 Phase 13-17에서 byte 동일성을 확인했다. 이번 기준점의 contract fixture 41개에는 HMAC 벡터와 새 versioned chat fixture가 포함된다. 오래된 관찰 fixture는 새 source hash로 다시 쓰지 않았다.

## 현재 소스에서 실행한 검사

| 명령 | 결과 |
| --- | --- |
| cargo test --locked --offline --manifest-path sasoo/backend-rust/Cargo.toml | 150 passed, 0 failed, 기존 ignored 3 |
| 위 명령에 --features pdf-xberg-native 추가 | 175 passed, 0 failed, 기존 ignored 3 |

두 명령은 겹치는 검사이므로 합산하지 않는다. 실제 rustc/cargo 1.94.1인 기존 stable alias와 작업 전용 CARGO_TARGET_DIR를 사용했고 새 도구 설치나 provider 호출을 하지 않았다. 실논문 corpus가 필요한 retrieval 2개와 selection 1개는 기존 ignored 상태이며 새로 제외한 검사는 없다.

새 worktree에서 기존 Python test environment만 로컬 symlink로 연결했다. venv는 Git에 들어가지 않는다. 테스트는 이 worktree의 Git 소스와 fixture를 읽었다. 새 환경에서는 프로젝트 Python test dependencies와 Node, 고정 Cargo dependency cache가 필요하다. offline 명령이 빈 Cargo cache까지 준비해 주지는 않는다.

실제 listener 검사는 papers_http_oracle.py를 통해 합성 DB/실제 합성 파일과 Python 읽기 결과를 비교했다. auth/CORS/HEAD/405/query/422, 파일 containment, page 밖 trap, marker와 DB/sidecar/library 전후 hash를 검사한다. refresh/write/external socket counter는 0이다. PDF feature 검사는 별도 선택 기능의 합성 local process/HTTP 회귀이며 PDF 품질 또는 운영 채택의 증거가 아니다.

전체 검사 중 487개 기준 파일의 SHA-256이 같았다. 이후 독립 reviewer가 M1 문서의 PDF profile을 실제 native_options()와 같은 text-layer-v2로 정렬하도록 지적해, 문서 1개만 수정하고 별도 assert로 확인했다. 실행 코드와 fixture는 전체 검사 당시와 byte 동일하며 이 문서 변경의 전후 hash도 manifest에 기록했다. 전체 source 목록과 실제 로그 hash는 [manifest](m1-baseline-source-sha256.json)에 고정했다. 원래 작업 기록의 실행 로그는 로컬 docs/validation/rust-backend/assets/m1-baseline-20261116/에 보존하며 binary나 runtime DB는 이 커밋에 넣지 않는다.

기존 HTTP 캡처 HTML 3개와 vendor unified patch의 공백 때문에 git diff --check는 exit 2다. 관찰 bytes와 patch context를 보존하려고 이를 정규화하지 않았다. 새 코드/문서의 whitespace 검사는 별도로 확인하며 fmt/clippy 통과로 표현하지 않는다.

## M1 소유권과 다음 경계

- Codex: W02, W05, W06, W10. runtime(ledger.rs 제외), HTTP, analysis/graph.rs와 completion.rs, W01 config/accept 통합.
- 상대 세션: W03 ledger.rs, providers, 단계 실행기, 필요할 때 P06 legacy helper.
- 공용 Cargo.toml/Cargo.lock/lib.rs/각 mod.rs/storage/migrations.rs와 additive migration revision은 Codex만 통합한다. 상대 PR은 필요한 등록과 schema delta를 별도로 요청한다. 기존 revision 1 SQL을 바꾸지 않는다.
- 첫 runtime PR은 W06 graph의 StageInput/StageOutput/RunContext와 기존 계획 §4의 run_phase 경계를 고정한다. 구체 필드/async 계약은 아직 코드로 구현하지 않았다. W03/provider 타입은 상대 세션 소유이며 새 타입을 양쪽에서 중복 생성하지 않는다.
- W10은 M1의 격리 run/status/results 범위다. 미완료 W04/W07/W08/W09를 전체 W10 통과로 감추지 않는다. 기본 Phase 17과 production guard, cancel/active DELETE는 이 기준 커밋에서 확장하지 않는다.

## 검증 범위 밖

실제 SDK/유료 응답 기록/원격 결산, OS key-store, 실제 사용자 자료, GUI/설치본, Windows, fmt/clippy/새 CI, 생산 전환은 이번 기준 검사에서 안 돌려 봤음. 기존 Phase 13-17의 Python/UI 전체 검증은 별도 당시 source receipt이며 이 Rust baseline PR의 재실행 결과로 합산하지 않는다. 결과 채택 권한과 이미 발생한 usage 보존은 서로 다른 경계이며, EOF/HTTP 200/캐시 존재로 둘을 함께 확정하지 않는다.
