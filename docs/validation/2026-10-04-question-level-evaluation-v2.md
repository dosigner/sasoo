# Sasoo 질문별 정량 평가 v2 초안

작성일: 2026-10-04. 상태: **평가 설계 초안**. 새로운 모델 생성이나 v2 재채점은 수행하지 않았다. 기존 실험의 프롬프트, 원응답, 판정과 최종 보고서는 보존한다.

주된 변경은 질문 하나를 여러 개의 검증 가능한 내용 단위로 나누고, 내용 충족/정확성/출처/중대 오류를 질문마다 따로 측정하는 것이다. 특정 모델의 답변이나 문장 형태를 정답으로 삼지 않는다. v2의 모델 중립성은 설계 목표이며 아직 실증된 사실은 아니다.

## 기존 기준의 문제와 5.6 편향 의심

확인된 기록은 다음과 같다.

- [원문 기준표](2026-09-22-v1.0.1-paper-evidence.md)는 원문을 읽어 만든 기준이며 Sasoo의 생성 답변이 아니라고 명시한다. source manifest의 준비 시각은 2026-09-21이며 당시 model validation은 not_run이다. 이 기록은 출처에 대한 문서상 설명이고, 작성 과정 전체의 독립성을 증명하지는 않는다.
- [9월 22일 검증](2026-09-22-v1.0.1-summary-reading.md)은 같은 여섯 논문에서 GPT-5.6 Luna 프롬프트를 반복 보정했다. 이 세트를 이후 평가에도 재사용했으므로 모델/프롬프트 개발에 사용한 회귀 자료라는 성격이 있다.
- [9월 23일 비교](2026-09-23-gpt-6-luna-comparison.md)의 엄격 통과는 5.6이 1/6, 6이 0/6이었다. 5.6도 거의 모두 탈락했다는 사실만으로 기준의 공정성이 입증되지는 않으며, 이 작은 표본으로 5.6에 유리한 편향이 확정되는 것도 아니다.
- 이번 10월 A/B는 양쪽 모두 GPT-6 Luna를 사용했다. 이 사실은 프롬프트 효과와 모델 효과를 분리하지만, 평가 항목 선정의 편향까지 제거하지는 않는다.

따라서 **5.6 답변을 정답으로 삼았다고 단정할 근거는 부족하다. 다만 5.6 개발 과정과 같은 여섯 사례에 맞춘 기준을 범용 품질 척도처럼 사용한 위험은 있다.** 특정 모델에 유리한 방향과 크기는 별도 검증이 필요하다.

설계상 확인되는 문제는 세 가지다. 첫째, 복합 질문의 구성요소 하나가 빠져도 질문 전체를 0점 처리해 큰 누락과 작은 누락을 구분하지 못했다. 둘째, 특정 미보고 항목을 읽기 목적에 중요한지 별도 근거 없이 필수로 고정했다. 셋째, 묶음 출처를 모든 주장과 모든 출처의 조합으로 검사해 인용 방식에 과도하게 민감해졌다. 특히 이 마지막 규칙은 원문 사실 지지율과 다른 성격의 낮은 출처 지지율을 만들었다.

## v2의 질문별 채점 단위

기본 독자는 기존 조건과 같은 undergrad이며, 목적은 논문의 주장과 근거를 이해하는 것이다. 완전한 실험 재현에 필요한 전문 세부값은 확장 평가로 분리한다. 원문에 중요한 정보가 있는데 어렵다는 이유로 제외하지 않는다.

| 질문 | 원문에서 먼저 정할 내용 단위 |
|---|---|
| Q1 | 연구 대상/문제, 필요한 이유 또는 기존 한계, 연구 목표 |
| Q2 | 핵심 입력/처리/출력, 작동 이유, 결론을 성립시키는 가정 |
| Q3 | 주요 지표의 정의, 결과값/단위, 비교 대상, 조건/범위, 보고된 불확실성 |
| Q4 | 저자가 보고한 핵심 한계, 일반화 범위, 분석자 해석의 근거와 귀속 |
| Q5 | 다른 상황에서 결론을 적용할 때 유지/확인해야 하는 인터페이스와 가정 |
| Q6 | 읽기/적용 판단에 중요한 미확인 정보, 제공 자료 범위, 보고됨/미제공/미보고/비적용의 구분 |

각 단위에는 원문 위치, 짧은 근거, 중요하게 선택한 이유와 허용되는 동등 표현을 붙인다. 선택자는 모델 답변과 과거 실패 목록을 보지 않는다. 숫자는 지표/대상/조건과 연결해 판정한다. 다른 대상에 붙인 95%를 숫자가 같다는 이유로 정답 처리하지 않는다.

핵심(core)과 확장(extension)을 평가 전에 구분한다. 예를 들어 T블록 질량/마찰이나 payload의 언급을 모든 일반 논문 설명에 일률적으로 강제하지 않는다. 해당 논문의 결론이나 고정된 사용 목적이 그 값에 의존하면 핵심 단위로 선정하고 이유를 남긴다. Bell의 실험 장치 보정처럼 적용되지 않는 항목은 원문/연구 유형에 따라 N/A로 정하며, 모델이 답변을 빠뜨렸다는 이유로 사후 N/A 처리하지 않는다.

## 질문마다 함께 보고할 숫자

| 지표 | 계산 |
|---|---|
| 내용 충족률 C | 정확하게 포함된 핵심 단위 수 / 적용 가능한 사전 핵심 단위 수 × 100 |
| 사실 지지율 P | 원문이 지지하는 고유 주장 수 / 질문에 해당하는 평가 가능 고유 주장 수 × 100 |
| 인용 근거 충분성 S | 붙인 출처 집합이 주장을 함께 지지하는 주장 수 / 출처가 붙은 주장 수 × 100 |
| 출처 유효성 U | 존재하며 연결된 주장 중 적어도 하나에 실제 기여하는 출처 수 / 출력한 출처 수 × 100 |
| 인용 충족률 L | 출처가 필요한 충족 핵심 단위 중 실제 출처를 붙인 수 / 해당 핵심 단위 수 × 100 |
| 중대 오류 E | 핵심 정의/수치/단위/방향/범위를 잘못 바꾼 근본 오류 수, 같은 오류의 반복은 중복 제외 |
| 거짓 부재율, Q6 | 원문에 있는데 없다고 한 주장 수 / 출력한 부재 주장 수 × 100 |

단위별로 정확한 충족은 1, 누락/오답/근거 불충분/해소되지 않은 모순은 0으로 기록한다. 애매한 복합 항목에 임의의 0.5를 주기보다 독립 판정 가능한 구성요소를 미리 나눈다. 따라서 **핵심 단위 5개 중 4개를 정확히 설명하고 1개를 빠뜨린 가상 예시는 C=80%**다. 이 예시는 실제 A/B 응답의 새 점수가 아니다.

같은 사실을 반복해도 가점을 주지 않는다. 정확하지만 핵심 목록 밖의 설명을 늘려도 C는 올라가지 않는다. 문장을 다시 표현하거나 필드를 옮겼다는 이유로 점수를 바꾸지 않는다. 근거 있는 분석자 추론은 추론으로 표시했는지와 전제/도출을 함께 확인한다. 동일 내용을 맞게도 틀리게도 쓰면 올바른 문장이 오답을 지워 주지 않는다.

두 출처가 서로 다른 부분을 보완해 한 주장을 뒷받침하면 S에서 인정한다. 불필요하거나 잘못된 출처를 덧붙인 경우 U에서 드러난다. 한 출처의 결함 때문에 해당 질문의 내용 점수나 논문 전체 점수를 0으로 만들지 않는다. 분모가 0이면 N/A이며, 아무것도 쓰지 않은 답은 필요한 핵심 단위가 있는 한 C=0이다.

질문마다 `C / P / S / U / L / E`를 보여 주고 Q6에는 거짓 부재율을 더한다. 임의로 50:30:20 같은 가중 합산이나 새 PASS 문턱을 만들지 않는다. 전체 충족률이 필요하면 논문 안에서 적용 가능한 질문을 동일 비중으로 평균하고, 논문 사이도 동일 비중으로 평균한다. 분모와 N/A 수를 함께 공개한다.

## 모델 중립성을 확인할 절차

1. 원문과 읽기 목적만 보는 작성자가 정답 단위/중요도/허용 표현을 정하고 고정한다. 5.6이나 6의 답변을 모범 답안으로 사용하지 않는다.
2. 익명 패킷의 파일명, 경로와 메타데이터에서도 모델명과 조건을 제거한다. 앞선 평가에서 모델명이 경로에 남았던 한계를 없앤다.
3. 모델 라벨 교환, 제시 순서 반전, 의미가 같은 문장 재표현, 중복 문장 추가에 대해 판정이 안정적인지 확인한다. 짧게 쓰기와 근거 없는 추가 설명으로 점수를 올릴 수 있는지도 검사한다.
4. 기존 여섯 편은 개발/회귀 세트로 유지한다. 이 자료를 v2로 다시 채점하면 결과를 본 뒤 만든 기준에 따른 탐색 분석으로 표시한다. 일반화 주장은 사용하지 않은 논문에서 단위 목록을 먼저 고정하고 검증한다.
5. 사람 전문가의 질문별 판정과 비교해 자동 검토자의 일치도/오류 유형을 확인한 뒤 운영 기준을 정한다. 모델 이름이나 원하는 승자에 맞춰 단위/가중치/통과선을 고르지 않는다.

## 이번에 완성한 것과 남은 검증 범위

[기계 판독용 명세](assets/question-eval-v2-20261004/metric-spec.json), [기준 이력 감사](assets/question-eval-v2-20261004/provenance.json), 기존 질문별 분해 CSV를 작성했다. [재계산 검사](assets/question-eval-v2-20261004/check_design.py)는 가상 산술, 중복/확장 문장의 C 불변성, N/A와 기존 25/36 및 27/36 합계를 검사한다. 새 생성/count API 호출은 0회다.

v2의 논문별 핵심 단위 목록과 새 질문별 점수는 아직 작성/측정하지 않았다. 이번 산출물은 그 점수를 계산하는 방식과 모델 편향을 줄이는 작성 절차의 초안이다. 기존 `candidate_failed` 기록을 새로운 기준으로 소급 덮어쓰지 않는다. 다음 v2 채점에서는 원문 단위 목록과 점수표를 함께 제출해야 한다.

핵심 원칙은 평가의 분모를 모델이 쓴 답변이나 과거 특정 오류 목록에만 맡기지 않는 것이다. 원문과 사용 목적에서 분모를 먼저 정하고 질문별 충족, 정확성, 근거와 오류를 분리해야 어느 모델이 어떤 일을 잘했는지 확인할 수 있다.
