# Sasoo 1.0.1 상세 요약과 읽기 검증

상태: 기능 구현, 자동 검사와 개발 앱 GUI 검증 완료. 최종 화면 178장에 대한 새 독립 구조/시각 검토는 모두 PASS다. 세 번째 실제 모델 검증까지 수행했으나 여섯 편의 과학적 정확성 게이트는 미통과다. Task 6 전체 완료와 1.0.1 배포 준비 완료로 판정하지 않으며 버전 정렬과 macOS 패키지는 계획의 선행 조건에 따라 보류한다.

## 구현 판단과 계획 보완

1. 생성 응답에 두 확장 배열을 필수로 요구하고, 저장 결과에 두 키가 모두 없을 때만 구형으로 읽는다. 부분 누락, 타입/열거값/상한/출처 오류를 기본값으로 덮지 않는다.
2. 기존 모델 어댑터는 완료 상태를 버리고 공통 경로는 잘린 JSON을 복구할 수 있었다. 심층 분석에 한해 `incomplete`를 전달하고 실패로 기록하며, 잘린 요약을 복구하여 성공시키지 않는다. 출력 상한은 그대로 16,000이다.
3. 기존 report API는 있었지만 프런트엔드 Markdown/HTML 다운로드 진입점은 없었다. 요약 하단에 형식 선택과 다운로드 버튼을 추가하여 요청된 R7을 충족한다. 기존 GET과 Markdown 렌더러, 다운로드 함수를 재사용하며 새 모델 호출은 없다.
4. 별도 문서 스타일과 `codeTools` 옵션만 확장한다. 채팅, 라이브러리, 설정에 `reading-prose`를 적용하지 않는다.
5. 실제 GUI에서 저장 시각화가 없을 때 `useAnalysis`가 생성형 `GET /mermaid`를 자동 호출함을 발견했다. 네트워크/서버 로그, 호출부와 원격 모델 경로, 빈/실패 시각화 두 경우의 실패 테스트로 원인을 확인했다. 조회 훅의 이 자동 생성 폴백만 제거한다. 기존 API의 명시적 생성 동작과 관련 테스트는 유지하며, 저장 결과를 읽는 경로는 새 요청을 만들지 않는다. 임시 계측 코드는 앱에 추가하지 않았다.
6. 손상된 저장 확장의 오류 상태를 `getSummaryDisplayStatus`가 판정하고 패널과 상위 워크벤치가 재사용한다. 완료 헤더와 오류 본문이 동시에 표시되던 모순을 실패 테스트로 재현하고 수정했다.
7. 답변 이동 시 `scrollIntoView`가 바깥 레이아웃까지 240px 스크롤하는 문제를 실제 화면에서 확인했다. `focusReadingTarget`은 읽기 패널만 상대 좌표로 이동한다. 수정 후 바깥 scrollTop은 0, 패널 y는 240으로 유지된다. 320px 패널의 탭은 글자 대신 버튼 단위로 줄바꿈하며 표 셀은 최소 8rem에서 내부 스크롤한다.
8. 독립 시각 검토는 비활성 버튼의 opacity가 오류 설명에까지 적용되는 대비 문제를 발견했다. 오류 원인은 버튼 밖의 별도 안내로 옮기고 기존 danger-fg를 적용했다. 단계 설명도 단어 단위로 줄바꿈한다. 내보내기 자동화의 바깥 스크롤은 캡처 절차를 고쳤으며 적용 조건 세 종류의 전체 내용 캡처를 추가했다.
9. 실제 실패 응답의 `_parse_error`/`error` 메타데이터는 구형 성공 결과로 읽지 않는다. 건너뛴 분석의 저장 `message`는 본문으로 보존하고 구형 재생성 안내와 혼동하지 않는다. 수정 전 실패 및 이후 통과 테스트를 추가했다.
10. 건너뛴 심층 분석은 백엔드의 기존 저장/종료 계약을 유지하면서 프런트 표시 상태에서 `skipped`로 구별한다. 단계 헤더와 단계 목록은 성공 체크 대신 중립적인 ‘건너뜀’을 표시한다. 진행 중인 새 분석은 이전 skipped 결과로 덮지 않는다.
11. 긴 실제 분석에서 그림 클릭 직후 Markdown의 인용 목록이 매번 새로 만들어져 답변 DOM이 교체되고 스크롤이 1,792px에서 344px로 줄어드는 회귀를 재현했다. 인용 목록을 메모화하여 기존 DOM을 유지하고 근거 이동도 패널 내부의 `auto` 이동으로 통일했다. 보충 그림을 본문 그림으로 오인한 부분 매칭은 새 `source_refs`에서만 완전 일치로 제한한다.
12. Bell PDF의 JBIG2 이미지가 기존 뷰어에서 빠지는 문제는 글꼴/CSS와 별개였다. 설치된 PDF.js의 WASM 파일을 개발 서버와 빌드에 포함하고 `wasmUrl`을 지정했다. CSP에는 WASM 실행 허용만 추가했다. 같은 원본의 8개 이미지 영역(페이지 전체 이미지 1개와 독립 수식 7개)을 Chrome과 개발 Electron `file://`에서 원문과 대조했다. PDF가 보이는 사실을 모델 입력 OCR의 복원으로 해석하지 않는다.

## 실제 입력과 과학적 검증

원문 목록과 여섯 질문 기준 답은 [원문 근거표](2026-09-22-v1.0.1-paper-evidence.md), 해시와 제공 범위는 [manifest](assets/v1.0.1-summary-reading/papers/manifest.json)에 기록한다. 원문 확보, 고정 fixture 검사, 실제 모델 생성 검증은 별개다.

사용자가 US$1 한도의 실제 모델 검증을 승인했다. OpenAI / gpt-5.6-luna / high, 기존 설명 수준 undergrad를 유지한다. 첫 캠페인 8건과 보완 후 6건의 합산 앱 환산 비용은 US$0.2364938이다. 중복 키, 출처 오인과 방법 원리/한계의 오류를 발견했으며 [바이오](assets/v1.0.1-summary-reading/models/revision-2/bio-review.md), [로보틱스](assets/v1.0.1-summary-reading/models/revision-2/robotics-review.md)의 독립 검토는 FAIL이다. 원응답과 비용을 보존했고 과학적 통과로 바꾸지 않았다.

세 번째 캠페인은 같은 PDF를 앱의 `ensure_text_artifacts`와 `load_or_build_document_context`로 처리한 [입력](assets/v1.0.1-summary-reading/papers/app-inputs.json)을 사용한다. PDF 해시는 같고 추출 텍스트 해시는 별도 기록한다. 새 결과는 실제 `_run_deep_dive` 함수를 실행하며 저장/캐시 접근만 검증용으로 격리한다. 비교 두 건도 같은 새 입력으로 다시 생성한다. 이는 전체 분석 파이프라인을 모두 실행한 검증은 아니다.

수정은 심층 분석의 legacy critic 성격/체크리스트 제외, OpenAI 요청 복사본의 strict schema, 중복 JSON 키와 비표시 제어문자 거부다. 공통 schema의 선택 필드와 저장 타입, 16,000 상한, 다른 분석 단계의 persona와 기존 재시도 정책은 유지한다. 수치나 정답을 출력에 맞춰 수정하지 않는다. 앱 단가 계산 총액을 누적해 US$1을 넘기기 전에 중단한다.

세 번째 캠페인까지 **생성 실행 22건, 입력 406,708 tokens, 출력 229,621 tokens, 누적 요청 경과 1,563.045초, 앱 환산 비용 US$0.3568868**을 기록했다. 출력 토큰에는 reasoning이 포함되므로 다시 더하지 않는다. [전체 사용량](assets/v1.0.1-summary-reading/models/all-usage.json)에 각 실행을 보존했다. 완료된 생성 실행 수이며, 공급자 내부/전송 계층의 재시도 횟수를 직접 계측한 수치는 아니다.

| 동일 앱 입력의 단회 비교 | 기존 → 개선 출력 tokens | 기존 → 개선 비용 | 기존 → 개선 경과 시간 |
|---|---:|---:|---:|
| bio1 | 7,876 → 10,188 (+29.36%) | US$0.0112916 → 0.0142586 (+26.28%) | 57.188 → 65.215초 |
| robotics1 | 8,584 → 10,104 (+17.71%) | US$0.0124120 → 0.0144372 (+16.32%) | 71.370 → 63.795초 |

새 답변과 조건의 분리에는 출력 비용이 더 든다. 이번 두 단회 시간 측정으로 보편적인 속도 개선/악화를 주장하지 않는다. [반복 검사](assets/v1.0.1-summary-reading/models/revision-3/repetition-check.json)의 40자 이상 동일 문장 후보는 인용 절 제목 조각을 제외하면 실제 설명 문장 반복 0건이었다. 의미상 겹치는 방법/조건 설명은 있으며 바이오/로보틱스 검토 기록에 비용 증가와 실익을 함께 기술했다. 정확한 문자열 중복 0건이 의미상 반복 0건을 증명하지는 않는다.

현재 여섯 편의 과학적 완료 기준은 충족하지 못했다. 실패 결과를 수동 수정하거나 추가 호출에서 성공한 부분만 선택해 통과시키지 않았다. 모델 선택, 원문 입력 정책 또는 패키지 선행 조건을 바꾸는 후속 결정 없이 네 번째 내용 보정과 유료 호출을 계속하지 않는다.

[검증 실행기](assets/v1.0.1-summary-reading/run-model-validation.py)의 무과금 dry run은 6편의 PDF/텍스트 해시, 기존 커밋 지시문, 현재 지시문과 시스템 지시문 조립을 확인했다. 입력은 앱의 기존 OpenAI 텍스트 상한 150,000자를 따른다. Bell 원문의 OCR은 수식을 누락하므로 텍스트 경로의 출력만으로 수식 정확성을 통과 처리할 수 없다. 리뷰의 입력 절단 범위도 원문 대조에 기록했다. 실행별 입력/출력 토큰과 reasoning 토큰, 앱 단가 환산 비용, 시간, 반복 문장과 구조 검사 결과를 보존했다. 앱 단가 환산값은 공급자의 최종 청구서와 동일하다고 주장하지 않는다.

## 실제 GUI

격리 데이터 폴더 `/tmp/sasoo-v101-gui-data`와 검증용 PDF/결과를 사용한다. 현재, 구형, 빈 배열, 형식 오류, 진행, 실패, 미생성, 중복 제목을 구분한다. 생성 POST는 검증 환경에서 차단한다. 실제 논문의 과학적 결과로 fixture를 사용하지 않는다.

실제 Chrome에서 4개 창 크기(1024×680, 1280×800, 1400×900, 1600×1000), 분할 1:1/1:2/2:1, 문서 폭 320/375/560/768px, 밝은/어두운 테마를 확인했다. 질문/답 기본 노출, 접기 상태, 정확 연결과 전체 요약 폴백, 같은 링크 재클릭, 근거 이동과 요약 scrollTop 복원, 코드 원문 복사 성공/실패, 키보드, reduced motion, Markdown/HTML 실제 다운로드를 조작했다. 전체 결과는 [gui-checks.json](assets/v1.0.1-summary-reading/gui/gui-checks.json)의 확인 항목과 캡처 manifest를 따른다. 합성 fixture 검증을 실제 모델 품질 검증으로 대신하지 않는다.

2026-09-22 07:48 KST에 [최종 캡처 manifest](assets/v1.0.1-summary-reading/final-capture-manifest.json)를 고정했다. 소스 19개의 해시와 최종 소스 수정 후 촬영한 PNG 178장의 signature/크기/해시/비어 있지 않음을 확인했다. 구성은 합성 fixture 106장, 실제 모델 결과 61장, 개발 Electron 확대 2장, decoder/긴 요약 스크롤/보충 참조 9장이다. 최신 합성 fixture 검사는 202/202이며 HTTP/console/JavaScript 오류와 생성 요청은 0이다. [구형 화면과의 차이](assets/v1.0.1-summary-reading/final-image-diff.json)는 동일 1400×900 light/1:1 상태의 픽셀 차이 0건으로, 마지막 decoder 수정이 이 화면의 모양을 바꾸지 않았음을 확인한다. 이 한 장의 일치가 전체 화면의 품질을 증명하지는 않는다.

[최종 독립 시각 검토](assets/v1.0.1-summary-reading/final-visual-review.md)는 새 검토자 두 명이 모두 PASS를 반환했다. 구조 검토는 소스 19개와 전체 범주/기능 경로를 대조했고 시각 검토는 178장 전부를 직접 열었다. 차단 사항은 없으며 현재 소스와 전체 캡처의 해시를 보고서에 묶었다. [이전 독립 검토](assets/v1.0.1-summary-reading/final-visual-review-before-real-paper-fix.md)는 과거 빌드 기록으로만 보존한다.

Electron은 별도 프로필과 데이터 폴더, 포트 18173에서 현재 빌드한 프런트엔드를 file URL로 열어 검사했다. 개발 모드의 고정 포트 8000은 이미 실행 중인 사용자 앱이 사용하므로 테스트 wrapper에서만 포트와 프런트 URL을 바꿨다. 사용자 앱을 종료하지 않았다. 창 크기 1400×900을 요청했지만 마지막 macOS 실측은 작업 영역에 맞춰 1400×872였다. 실제 `webContents.setZoomFactor(2)`로 논리 700×436이 된 상태에서 답변 이동, 가로 넘침 없음, 바깥 scrollTop 0, 생성 요청 0, JavaScript 오류 0을 확인했다. 브라우저의 1400×900 검사와 구별한다. [native-checks.json](assets/v1.0.1-summary-reading/native/native-checks.json)과 [200% 화면](assets/v1.0.1-summary-reading/native/electron-1400-200pct.png)을 참조한다. 이것은 패키지 실행 검증이 아니다.

캡처 도구 제한: Playwright의 Electron 확대 화면 캡처가 일부 영역만 저장하는 것을 픽셀 크기로 확인했다. Electron `webContents.capturePage`로 바꾸어 다시 캡처했다. 또한 배율 변경 직후 캡처에는 이전 프레임이 남을 수 있어, 최종 캡처는 원하는 `innerWidth`, 폰트와 PDF 페이지 준비, 두 animation frame을 기다린다. `native-checks.json.frames`에 각 캡처의 zoomFactor 1/2와 논리 폭 1400/700을 별도로 기록했다. Chrome의 CSS zoom 2 검사와 Electron의 실제 zoomFactor 2 검사는 구별한다.

실제 생성 결과는 원문 PDF와 응답 해시를 고정하여 여섯 편 모두 앱에서 열고 답변, 근거, 스크롤 복귀와 Markdown/HTML 내보내기를 확인했다. 자동 확인은 175개 중 173개 통과, 아래 두 조건의 실패와 raw exit 1을 보존한다. 읽기 안내와 그림/표 위치는 연결 검증용으로 준비한 자료다. 이 검사를 읽기 안내의 실제 생성이나 전체 분석 파이프라인 검증으로 확대하지 않는다. 심층 분석만 저장한 데이터이므로 종합 뷰 조회의 404/console 메시지 12건과 리뷰 PDF의 `TT: undefined function: 32` 경고 2건을 그대로 기록한다. JavaScript 예외, 예기치 않은 페이지 이동과 새 생성 요청은 0이다.

내보낸 HTML이 Vite의 소스 감시를 자극하여 `full-reload`가 발생한 캡처 실패도 [검증 도구 실패 기록](assets/v1.0.1-summary-reading/model-gui/capture-tooling-failures/)에 보존했다. WebSocket의 `triggeredBy`가 실제 `report.html`을 가리키는 것을 확인하고 QA 서버에서만 검증 산출물 폴더를 감시 대상에서 제외했다. 제품 코드와 실패 기대값은 바꾸지 않았으며 마지막 6편 실행의 reload frame은 0이다.

모델 GUI 자동화의 `nonexperimental-as-is-to-be-empty` 두 검사는 실패 상태와 원응답을 보존했다. 이는 모든 이론/리뷰의 두 필드가 반드시 비어야 한다는 하네스 가정이다. 명세 §2의 조건은 해당 구도가 없으면 비우고 공학식 구도를 강요하지 않는 것이다. [수동 범위 판정](assets/v1.0.1-summary-reading/model-gui/manual-scope-review.md)은 실제 이론의 가정/정리 목표와 리뷰의 기존 접근/조사 목표를 원문과 대조한다. 이 판정을 자동 실패 삭제나 여섯 편의 과학적 정확성 통과로 표현하지 않는다.

Bell 원문은 [Chrome decoder 검사](assets/v1.0.1-summary-reading/model-gui/pdf-decoder-chrome-dev.json)와 [Electron file URL 검사](assets/v1.0.1-summary-reading/model-gui/pdf-decoder-electron-file.json)에서 동일 PDF 해시와 JBIG2 8영역의 실제 표시를 확인했다. 독립 수식은 7개다. decoder 경고와 JavaScript 예외, 생성 요청은 없었으며 종합 뷰 결과 없음에 따른 404는 구분한다. 긴 DESeq2 결과의 native normal/reduced motion 검사는 모두 scrollTop 3,330→3,330, 원래 답변 DOM 유지, 바깥 스크롤 0을 기록했다.

취소 검증은 합성 running 상태에서 실제 취소 API의 응답과 전체 취소 표시까지 확인했다. 기존 엔진은 실행 중인 모델 단계를 다음 checkpoint에서 중단하므로, worker가 없는 fixture에서 남은 phase.running을 실제 모델 종료 증거로 해석하지 않는다. 실제 모델 작업의 취소 완료 시점은 미검증이다.

검토 종료 후 검증용 8171/5179 서버와 native QA 포트가 종료됐음을 [정리 기록](assets/v1.0.1-summary-reading/cleanup.json)에 남겼다. 실행 중인 사용자 8000 앱의 프로세스는 유지했고 사용자 데이터와 검증 증거는 삭제하지 않았다.

## 패키지와 미검증 범위

- 버전 동기화 및 macOS 패키지: 비용 승인은 받았고 실제 검증도 실행했으나 과학적 완료 기준이 미충족이라 Task 7의 선행 조건을 충족하지 못했다. 네 버전은 아직 1.0.0이며, 패키지 완료로 보고하지 않는다. Python 3.12와 별도 소스 사본 준비만 완료했다.
- Windows: 이 macOS 환경에서는 실행 검증하지 않는다.
- 실제 사용자 학습 효과: 이번 결과물 검토를 사용자 대상 실험으로 표현하지 않는다.

완료 단계는 Task 1~5와 Task 6의 코드/근거표/실제 호출 및 GUI 검증이다. Task 6의 과학적 판정과 Task 7의 버전/패키지는 보류이며, 변경 요약과 한계 기록은 완료했다. 원격 push, release tag 생성과 GitHub release 공개는 하지 않았다.
