## 3. 지연

평소 턴(`ttft.py`, 측정): 같은 백엔드에 persist 켬(2단계 경로)과 끔(DB를 거치지 않는 1단계 경로)을 번갈아 5쌍씩 보냈다. 쌍마다 기록을 지워 맥락 크기를 같게 두었다. 평소 턴은 계산 API를 부르지 않는다.

| 프로바이더 | persist 끔 중앙값 | persist 켬 중앙값 | 차이 |
|---|---|---|---|
| OpenAI gpt-6-luna | 0.85초 | 0.91초 | +0.05초 |
| Gemini gemini-3.8-flash | 3.77초 | 3.92초 | +0.15초 |

Gemini의 표본 범위가 2.28~12.66초라 차이는 잡음 안에 있다. 원문은 `ttft-result.json`이다.

계산 API를 부르는 턴(`precount_big.py`, 측정): 대화 기록 형태의 한국어, 영어 혼합 문장으로 약 23만 토큰을 만들어 5회씩 셌다.

| 프로바이더 | 입력 토큰 | 왕복 중앙값 | 최대 |
|---|---|---|---|
| OpenAI `responses.input_tokens.count` | 231,326 | 0.65초 | 0.72초 |
| Gemini `models.count_tokens` | 231,513 | 0.85초 | 1.01초 |

두 값 모두 0.5초 기준을 넘는다. 이 턴은 마지막 실제 입력 토큰에 글자 수를 더한 추정이 234K를 넘을 때만 생기므로, 예산 끝의 몇 턴에 한정된다. 같은 측정에서 이 혼합 문장은 글자 하나가 약 0.56토큰이었다. 따라서 글자 하나를 토큰 하나로 보는 추정은 계산 API를 실제보다 일찍 부르는 방향으로 틀린다(추론).

## 4. OpenAI 계산 API의 비용과 레이트 리밋

- 1차 문서: [Counting tokens](https://developers.openai.com/api/docs/guides/token-counting) 가이드와 [Rate limits](https://developers.openai.com/api/docs/guides/rate-limits) 가이드 모두 이 엔드포인트의 과금과 레이트 리밋을 적지 않았다(2026-10-09 확인). API 레퍼런스의 해당 페이지 주소는 404였다.
- 2차 자료: [커뮤니티 답변](https://community.openai.com/t/does-post-responses-input-tokens-cost-money/1380071)은 "It is free (with a funded API account…)"라고 쓴다. OpenAI 직원의 답은 아니다.
- 실측: `POST /v1/responses/input_tokens`는 200과 `input_tokens`를 돌려주지만 `x-ratelimit-*` 헤더를 보내지 않았다. 그래서 응답만으로는 RPM, TPM 한도에 포함되는지 알 수 없다.
- 영향: 이 호출은 234K 초과 턴에서만 한 번 생기고, 실패하면 추정값으로 판정한다(`_count_chat_tokens`가 None을 돌려준다). 과금되거나 한도에 잡혀도 그 턴에 한 번이다.

## 5. 다중 턴 말투 게이트

조건: `multiturn_gate.py`가 이 브랜치 백엔드의 실제 채팅 경로(persist, 서버 기록으로 맥락 조립)에 논문마다 5턴을 차례로 보냈다. 턴 순서는 맞는 해석, 과장된 해석, 틀린 해석, 비판 요청, 후속 질문("방금 비판한 내용 중 첫 번째 근거는 논문 어디에 있어?")이다. 앞의 4개 발화는 1단계 게이트와 같다. 논문 2편(999006, 999004), 두 프로바이더, 대화 3회씩, 총 60턴이다. 시드는 없고 결과는 비결정적이다. 판정, 선인정, 반론 여부는 오케스트레이터가 원문을 읽고 판단했다(추론). 인용 포함은 정규식으로 셌다.

| 지표 | 기준 | OpenAI | Gemini |
|---|---|---|---|
| 판정 정확(맞는, 과장, 틀린 해석) | 전부 | 18/18 | 18/18 |
| 근거 위치 인용 포함 | 1단계 비율(32/42) 이상 | 30/30 | 30/30 |
| 과장 주장에서 맞는 범위 먼저 | 4/6 이상 | 5/6 | 4/6 |
| 비판 요청에서 근거 없는 반론 | 0/6 | 0/6 | 0/6 |
| 후속 질문이 직전 비판의 첫 항목을 가리킴(새 기준) | | 6/6 | 6/6 |
| 후속 질문에 반론 | 0 | 0/6 | 0/6 |
| 인용 위치 PDF 대조(합산 10건) | 지어낸 위치 0 | 0/10(합산) | |
| 비용(30턴, 측정) | | $0.0087 | $0.2958 |
| 첫 토큰 중앙값(측정) | | 1.39초 | 6.63초 |

- 맥락 누적: 턴별 평균 입력 토큰이 OpenAI 7,298 → 8,404, Gemini 7,220 → 9,538로 늘었다. 60턴 모두 `done`으로 끝났고 대화마다 10행이 complete로 저장되었다.
- 선인정 실패 3건: OpenAI 999006 3회차("아니, 논문이 보인 건 …"), Gemini 999006 1회차("그건 논문이 실제로 보여준 내용과는 완전히 달라."), Gemini 999004 2회차("그건 논문 내용과 달라."). 1단계 단일 턴의 6/6보다 낮다. 직전 턴에서 맞는 해석을 확인한 뒤라 과장 주장을 반박으로 받는 경향으로 보이지만, 표본 6건이라 원인은 확정하지 못했다(추론).
- 후속 질문에서 OpenAI 999006 3회차는 앞 턴의 위치 인용("표 1")이 틀렸다고 스스로 정정했다. 60% NFE 문장은 실제로 9쪽 본문에 있고 Table 1에는 없다.
- PDF 대조 10건: 60% NFE(9쪽 본문), 조건부 OT가 주변 벡터장의 OT를 뜻하지 않는다는 문장(6쪽 4절), Table 2 초해상도(FM w/ OT FID 3.4와 IS 200.8은 SR3보다 좋고 PSNR 24.7과 SSIM 0.747은 낮음, 9쪽), Fig. 7(9쪽), dopri5(7쪽), Uplink Table 1(4쪽, 등가층 2개, 2,500 m와 5,000 m, r0 100 mm), 8.6배(1쪽 초록, 10쪽 결론), 서론 인용문 "We present simulation results of this method"(2쪽), frozen flow 약 20 ms(2쪽). 모두 원문과 맞았다.

원문: `assets/discussion-stage2-20261009/results-multiturn.json`. 총비용 $0.305(측정).

## 남은 것

1. 강제 계산 턴의 0.65~0.85초를 받아들일지 정한다. 대안은 계산 API를 빼고 추정값만으로 초기화하는 것이다. 그러면 지연은 없지만, 이 측정의 글자당 0.56토큰 기준으로 실제 예산보다 일찍 초기화된다.
2. Gemini 선인정이 기준 경계(4/6)다. 다중 턴에서 떨어지는 경향이 반복되면 규칙 문단을 다시 다듬는다.
3. Electron 셸(글래스 효과)에서의 화면 확인은 병합 뒤 개발 앱이나 릴리스 빌드에서 한다(미검증).
